## Summary

A patch with two changes: vela-core creates its own webhook and cluster-gateway certificates, so
the chart installs again on Kubernetes 1.36 and later, and outbound HTTP from workflows is guarded
against cloud-metadata and link-local addresses. v1.9 is end of life; upgrade to v1.10.10 or later
for the image fixes listed under Known issues.

## Breaking changes

- **`helm upgrade --reuse-values`.** With the values of v1.9.14 the chart fails to render, because
  the new `workflow.httpDeny` and `featureGates` values are missing. Pass your own values file, or
  use `--reset-then-reuse-values` (Helm 3.14 and later).
- **Workflow HTTP guard.** Outbound HTTP made by vela-core for workflows, and for addon and Helm
  repository fetches, refuses cloud-metadata and link-local addresses, and reads more deny lists
  from labelled ConfigMaps. A step that calls such an address now fails
  ([#7536](https://github.com/kubevela/kubevela/pull/7536)).
- **Runtime certificates.** vela-core creates and renews the admission webhook and cluster-gateway
  serving certificates and sets their `caBundle`, instead of the `kube-webhook-certgen` Jobs. The
  Secrets those Jobs created are reused. Argo CD and Flux users need to ignore
  `.webhooks[].failurePolicy` on both webhook configurations
  ([#7480](https://github.com/kubevela/kubevela/pull/7480)).

## Controller flags and feature gates

| Name | Change | Default |
| --- | --- | --- |
| `--webhook-tls-secret`, `--webhook-configuration`, `--webhook-failure-policy`, `--webhook-conversion-crds` | New | Set by the chart |
| `--cluster-gateway-tls-secret`, `--cluster-gateway-service` | New | Set by the chart |
| `--workflow-http-deny-config-template-name` | New | `vela-core-http-deny` |

## Helm chart changes

| Value | Change | Default |
| --- | --- | --- |
| `workflow.httpDeny.*` | New: deny lists for the workflow HTTP guard | `configTemplateName: vela-core-http-deny` |
| `featureGates.disableWorkflowHTTP`, `featureGates.blockPrivateHTTPAddresses` | New | `false` |

## Bug fixes

- A fresh `helm install --wait` completes on Kubernetes 1.36 and later
  ([#7480](https://github.com/kubevela/kubevela/pull/7480)).

## Known issues

- This release does not include the eMudhra CA and Brotli (CVE-2026-111497) image fixes. The
  vela-cli image is built on Alpine 3.15, cluster-gateway stays on `v1.9.0-alpha.2`, and
  `build-push-image` defaults to `oamdev/kaniko-executor:v1.9.1`. Upgrade to v1.10.10 or later for
  those fixes.
- Loopback addresses are not refused, and there is no timeout or response-size limit on workflow
  HTTP requests. v1.10.10 and later add them.
