## Summary

v1.9 removes the legacy APIs from KubeVela before v1.0, moves the image, chart and addon
registries to GitHub, and adds pause reconcile, multiple policies of the same type, a resource
update policy and multicluster `vela adopt`. It supports Kubernetes v1.26.

## Compatibility

| Component | Version |
| --- | --- |
| Kubernetes | Tested with v1.26 |
| Go | 1.19 |
| CUE | v0.5.0 |
| Kubernetes client libraries | `k8s.io/client-go` v0.26.3, `controller-runtime` v0.14.6 |
| Upgrade from | v1.8.x; see the [upgrade guide](/upgrade-guides/v1.9/) |

## Breaking changes

- **Legacy code removal.** You can no longer use EnvBinding, HealthScope, ScopeDefinition and
  other objects from KubeVela before v1.0, such as ApplicationConfiguration, `v1alpha2` Component
  and the legacy Rollout ([#6041](https://github.com/kubevela/kubevela/pull/6041),
  [#6068](https://github.com/kubevela/kubevela/pull/6068)).
- **Registry migrated to GitHub.** `hub.kubevela.net`, `charts.kubevela.net` and
  `addons.kubevela.net` will not be served in the future. Use `docker.io` or `ghcr.io/kubevela`
  for images, `kubevela.github.io/charts` for Helm charts and
  `kubevela.github.io/catalog/official` for addons; the
  [upgrade guide](/upgrade-guides/v1.9/) has the commands to update your addon registry.
- **Controller flags renamed or removed.** `--pprof-addr` is now `--profiling-addr`, and
  `--disable-caps` is removed. Update any custom controller arguments.
- **`ApplyResourceByUpdate` is renamed `ApplyResourceByReplace`.** Update `--feature-gates` if you
  set it.

## CRD changes

- The `healthscopes`, `scopedefinitions` and `standard.oam.dev` `rollouts` CRDs are removed from the
  chart.
- The `applications`, `applicationrevisions`, `componentdefinitions`, `definitionrevisions` and
  `traitdefinitions` schemas drop the legacy fields.

Apply the CRDs before `helm upgrade`; see the [upgrade guide](/upgrade-guides/v1.9/) for the commands.

## CLI changes

- `vela cuex eval` evaluates local CUE files with the CueX engine.
- `vela def gen-cue` and `vela def gen-doc` generate CUE and docs for providers.
- `vela adopt` works with multicluster resources, and `vela cluster join` can overwrite an existing
  cluster's kubeconfig.

## New features

- [Pause reconcile](https://github.com/kubevela/kubevela/pull/5732): label an Application
  `controller.core.oam.dev/pause: "true"` to stop reconciling it.
- [Same component name across Applications](https://github.com/kubevela/kubevela/pull/5727).
- [`check-metrics` workflow step](https://github.com/kubevela/kubevela/pull/5768) for Prometheus
  metrics.
- [Mode for step groups](https://github.com/kubevela/kubevela/pull/5799): DAG or StepByStep.
- [ProxyURL for multicluster](https://github.com/kubevela/kubevela/pull/5875).
- [Multiple policies of the same type](https://github.com/kubevela/kubevela/pull/5811), such as
  `apply-once` or `garbage-collect`.
- CueX validation for config templates, and multiple `gateway` traits on a component.
- [Configurable application revision limit](https://github.com/kubevela/kubevela/pull/5995) per
  Application, through a policy.
- [Resource update policy](https://github.com/kubevela/kubevela/pull/6003): `replace`, `recreate`
  or `patch`.
- [Force resource location](https://github.com/kubevela/kubevela/pull/6033) with the
  `app.oam.dev/cluster` label.
- [CRDs not required on the hub](https://github.com/kubevela/kubevela/pull/6008) for delivering
  CRD resources to managed clusters.
- [Custom cascading GC policy](https://github.com/kubevela/kubevela/pull/6059).
- [Version ranges for addon dependencies](https://github.com/kubevela/kubevela/pull/6002).

## Bug fixes

- Application GC is no longer blocked by ApplicationRevision GC.
- `vela addon registry add` follows redirects, and addon status lists the right registry.
- `vela def vet` works without Kubernetes.
- `component-pod-view` shows the pod IP, host IP and node name.
