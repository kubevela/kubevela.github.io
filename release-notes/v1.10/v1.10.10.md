## Summary

A security and fix release. Every image KubeVela ships or runs by default moves off the compromised
eMudhra CA chains, vela-core creates its own webhook and cluster-gateway certificates, outbound
HTTP from workflows and templates is guarded and limited, and about 45 fixes are backported.
Everyone on v1.10 should upgrade. Some fixes change behaviour, so read the breaking changes first.

## Breaking changes

- **`helm upgrade --reuse-values`.** With the values of v1.10.9 the chart fails to render, because
  the new `workflow.httpDeny` and `workflow.http` values are missing. Pass your own values file, or
  use `--reset-then-reuse-values` (Helm 3.14 and later). If your values set
  `multicluster.clusterGateway.image.tag`, update or remove it.
- **Workflow HTTP guard.** Outbound HTTP made by vela-core refuses cloud-metadata, link-local,
  loopback, unspecified and local-use NAT64 addresses, and reads more deny lists from labelled
  ConfigMaps ([#7535](https://github.com/kubevela/kubevela/pull/7535),
  [#7593](https://github.com/kubevela/kubevela/pull/7593)).
- **HTTP request limits.** A workflow or definition HTTP request fails if its timeout is zero,
  negative, has no unit or is longer than `workflow.http.maxTimeout` (`60s`), or if the response is
  larger than `workflow.http.maxResponseBytes` (1 MiB). The `request` step fails on an HTTP 400, and
  a step's TLS Secret is read only from the step's namespace
  ([#7593](https://github.com/kubevela/kubevela/pull/7593)).
- **`vela-cli` step.** Its Job runs in the Application's namespace as the service account named in
  `serviceAccountName` (default `default`), instead of in `vela-system` as vela-core. The step fails
  if that account does not exist ([#7593](https://github.com/kubevela/kubevela/pull/7593)).
- **Configs and SSH keys in other namespaces.** Configs read by config steps and Terraform module
  SSH keys are read only from the namespace that uses them. Move them there before you upgrade
  ([#7593](https://github.com/kubevela/kubevela/pull/7593)).
- **Runtime certificates.** vela-core creates and renews the admission webhook and cluster-gateway
  serving certificates and sets their `caBundle`, instead of the `kube-webhook-certgen` Jobs. The
  Secrets those Jobs created are reused. Argo CD and Flux users need to ignore
  `.webhooks[].failurePolicy` on both webhook configurations
  ([#7479](https://github.com/kubevela/kubevela/pull/7479)).

## Behaviour changes

- The Application's `Ready` condition goes `False` while a reconcile fails
  ([#7168](https://github.com/kubevela/kubevela/pull/7168)).
- A topology placement into another namespace is refused when `--allow-cross-namespace-resource`
  is off ([#7419](https://github.com/kubevela/kubevela/pull/7419)).
- CUE nested more than 1000 levels is refused before it is parsed.
- The query provider never returns a Secret's data. With `authentication.withUser=false`, a
  hand-written `app.oam.dev/username` is ignored. With
  `authorization.definitionValidationEnabled`, referenced Workflows and Policies are checked too.
- With cert-manager, or a certificate you supply, the webhooks use
  `admissionWebhooks.failurePolicy` (`Fail`) from the first install.

## Helm chart changes

| Value | Change | Default |
| --- | --- | --- |
| `workflow.httpDeny.*` | New: deny lists for the workflow HTTP guard | `configTemplateName: vela-core-http-deny` |
| `workflow.http.maxTimeout`, `workflow.http.maxResponseBytes` | New: the longest timeout and the largest response body a workflow or definition HTTP request may use | `60s`, `1048576` (1 MiB) |
| `featureGates.disableWorkflowHTTP`, `featureGates.blockPrivateHTTPAddresses` | New | `false` |
| `multicluster.clusterGateway.image.tag` | Changed from `v1.9.0-alpha.2` ([#7599](https://github.com/kubevela/kubevela/pull/7599)) | `v1.9.2`, pinned by digest |

For an air-gapped cluster, mirror `oamdev/cluster-gateway:v1.9.2` and
`ghcr.io/osscontainertools/kaniko:v1.29.1` by digest. `oamdev/kube-webhook-certgen` is no longer
pulled.

## Bug fixes

- The vela-core and vela-cli images are built on `alpine:3.24`, pinned by digest
  ([#7643](https://github.com/kubevela/kubevela/pull/7643)).
- The `build-push-image` step defaults to `ghcr.io/osscontainertools/kaniko:v1.29.1`; a step that
  sets `kanikoExecutor` keeps its image ([#7634](https://github.com/kubevela/kubevela/pull/7634)).
- A fresh `helm install --wait` completes on Kubernetes 1.36 and later
  ([#7479](https://github.com/kubevela/kubevela/pull/7479)).
- A `request` step succeeds on a reply that is not JSON, and `op.#HTTPDo` accepts
  `request.timeout` ([#7240](https://github.com/kubevela/kubevela/pull/7240)).
- A CUE error in a health or custom-status expression is logged and no longer fails the reconcile
  ([#7226](https://github.com/kubevela/kubevela/pull/7226)), and `vela status` no longer reports
  Healthy for a failed workflow ([#7234](https://github.com/kubevela/kubevela/pull/7234)).
- Panics fixed in the apply-once StateKeep path
  ([#7065](https://github.com/kubevela/kubevela/pull/7065)), on a malformed DefinitionRevision
  version ([#7207](https://github.com/kubevela/kubevela/pull/7207)), on malformed GitLab registry
  URLs ([#7206](https://github.com/kubevela/kubevela/pull/7206)), in `vela top` without a rest
  config ([#7279](https://github.com/kubevela/kubevela/pull/7279)) and in `#RenderComponent` with
  traits but no workload ([#7488](https://github.com/kubevela/kubevela/pull/7488)).
- Workflow `kube.#Delete` steps and pruning honour shared resources, garbage-collect rules and the
  orphan finalizer ([#7378](https://github.com/kubevela/kubevela/pull/7378)).
- `storage` `mountToEnv` replaces an environment variable of the same name
  ([#7217](https://github.com/kubevela/kubevela/pull/7217)), and `k8s-objects` with no objects no
  longer fails ([#6948](https://github.com/kubevela/kubevela/pull/6948)).
- Addons: `vela addon upgrade`, `status` and `disable` accept `<registry>/<addon>`
  ([#7357](https://github.com/kubevela/kubevela/pull/7357)), and GitLab registries with an empty
  base path work ([#6902](https://github.com/kubevela/kubevela/pull/6902)).
- `multicluster.clusterGateway.port` reaches the controller
  ([#7346](https://github.com/kubevela/kubevela/pull/7346)), and with cert-manager the gateway CA
  is read from `ca.crt` ([#7193](https://github.com/kubevela/kubevela/pull/7193)).
- CLI: `vela show` works for definitions that import `vela/*` packages
  ([#7017](https://github.com/kubevela/kubevela/pull/7017)), `vela auth` reads service account
  kubeconfigs ([#7425](https://github.com/kubevela/kubevela/pull/7425)), and
  `vela workflow rollback` continues at once.
- The OpenKruise rollout reverts when a rollback is paused at a canary step
  ([#7251](https://github.com/kubevela/kubevela/pull/7251)).
- A definition revision that an Application pins (`type@vN`) is never garbage-collected, and
  completed `webhook` and `notification` steps no longer run again after a stale-cache conflict
  ([#7593](https://github.com/kubevela/kubevela/pull/7593)).

The [GitHub release](https://github.com/kubevela/kubevela/releases/tag/v1.10.10) lists every
backported fix.
