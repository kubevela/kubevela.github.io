## Summary

A large patch release. It fixes a workflow HTTP security issue, and backports from master the
runtime certificate management, the built-in definitions hook Job, trait conflict enforcement and
about 50 other fixes. Everyone on v1.11.0 should upgrade. Read the breaking, behaviour and chart changes
below first: they are the same as in v1.12.0.

## Breaking changes

- **Trait conflicts.** Admission now rejects an Application whose traits conflict through
  `TraitDefinition.spec.conflictsWith`; see
  [Trait conflicts](/upgrade-guides/v1.12/#trait-conflicts)
  ([#7303](https://github.com/kubevela/kubevela/pull/7303)).
- **Workflow HTTP guard.** Workflow `request`, `webhook` and HTTP steps refuse metadata and
  link-local addresses, and read deny lists from labelled ConfigMaps
  ([GHSA-8p2m-f3vg-8jwg](https://github.com/kubevela/kubevela/security/advisories/GHSA-8p2m-f3vg-8jwg),
  [#7534](https://github.com/kubevela/kubevela/pull/7534)).

## Behaviour changes

- **Runtime certificates.** vela-core creates and renews the admission webhook and cluster-gateway
  serving certificates and sets their `caBundle`, instead of the `kube-webhook-certgen` Jobs. Argo CD
  users need `ignoreDifferences` for the webhook `failurePolicy`; see
  [Runtime certificates](/upgrade-guides/v1.12/#runtime-certificates)
  ([#7478](https://github.com/kubevela/kubevela/pull/7478)).
- PolicyDefinitions are validated with the compiler of their scope, and global and
  Application-scoped policy changes propagate to Applications
  ([#7531](https://github.com/kubevela/kubevela/pull/7531)).

| Value | Change | Default |
| --- | --- | --- |

| `controllerArgs.allowNamespaceGlobalPolicies`, `allowSkipGlobalPolicies` | New: global policy defaults | `true` |

## Bug fixes

- Resource keeper honours shared-resource, GC-propagation and orphan-finalizer protections on
  delete.
- `helmchart` keeps empty maps and lists in rendered manifests.
- External Package CRs are watched in the workload compiler.
- PolicyDefinition CUE is validated with the CueX compiler, and nonexistent provider functions are
  rejected.
- Workflow restart and trait output fixes ([#7488](https://github.com/kubevela/kubevela/pull/7488)).
- `vela auth` reads service account kubeconfigs, and `vela top` no longer panics without a
  rest config.
- `get-placements-from-topology-policies` respects `--allow-cross-namespace-resource`.
- `multicluster.clusterGateway.port` is propagated to the controller.
- The `sidecar` trait supports `ports`.
- The OpenKruise rollout reverts when paused at a canary step.
