## Uninstall

Before uninstalling kubevela, you must delete all applications and disable all addons.

1. Uninstall VelaUX

```
vela addon disable velaux
```

2. Uninstall KubeVela Core

```
vela uninstall
```

3. Uninstall CRD

Before deleting, you must delete all CR resources.

```
kubectl get crd |grep oam | awk '{print $1}' | xargs kubectl delete crd
```

## Install KubeVela with cert-manager

By default, vela-core generates a self-signed certificate for admissionWebhooks at startup and renews it. See [Runtime certificates](../upgrade-guides/v1.12/index.md#runtime-certificates) in the v1.11 to v1.12 upgrade guide.
You can also use cert-manager if it's available. Note that you need to install cert-manager **before** the KubeVela chart.

```shell script
helm repo add jetstack https://charts.jetstack.io
helm repo update
helm install cert-manager jetstack/cert-manager --namespace cert-manager --create-namespace --set crds.enabled=true
```

This installs the latest cert-manager. On an older cluster, add `--version <x.y.z>` with a cert-manager release that supports your Kubernetes version; see the [cert-manager supported releases](https://cert-manager.io/docs/releases/). The `crds.enabled` value needs cert-manager v1.15 or later; older releases use `installCRDs=true`.

Install kubevela with enabled certmanager:

```shell script
vela install --set admissionWebhooks.certManager.enabled=true
```

With cert-manager, the chart renders the webhooks with `admissionWebhooks.failurePolicy` (default `Fail`) from the start. Writes to Applications and definitions are refused until cert-manager has injected the CA bundle, and whenever no vela-core pod is ready. Run two or more replicas (`--set replicaCount=2`) to keep the webhook available during restarts.

## Admission webhook timeout

The `admissionWebhookTimeout` chart value sets the timeout, in seconds, of KubeVela's admission webhooks. The default is `10`. Raise it if validation of large Applications times out, for example:

```shell script
vela install --set admissionWebhookTimeout=20
```

## Feature gates ConfigMap

When the controller starts, it writes its feature gates to the `kubevela-feature-gates` ConfigMap in its namespace. It has one key per gate, with the value `true` or `false`. Tools that run beside the controller, such as VelaUX, read it to behave as the controller does.

## Install Pre-release

```
# List all releases
vela version list -a

# Install the specified version.
vela install --version 1.12.0-alpha.2
```

## Install Kubectl Vela Plugin

`kubectl-vela` provides the same features with `vela` CLI, it helps you to integrate with kubectl better.

kubectl krew update

kubectl krew install vela
