Deploy a crate.

### Synopsis

Build and apply an Application that installs a crate's enabled API lines, then report the install tiers as they become healthy.

```
vela crate deploy <crate> [flags]
```

### Examples

```
  Deploy a crate from the default registry:
	vela crate deploy s3

  Deploy from a named registry, into a namespace:
	vela crate deploy s3 --registry catalog -n platform

  Print the Application without applying it, capturing it for GitOps:
	vela crate deploy s3 --dry-run > s3-crate.yaml

  Put the crate's runtime objects on two managed clusters:
	vela crate deploy s3 --clusters spoke-a,spoke-b

  Put them on every cluster with a label, even when none match yet:
	vela crate deploy s3 --cluster-selector tier=runtime --allow-empty
```

### Options

```
      --allow-empty                       Do not fail when --clusters or --cluster-selector selects no cluster.
      --cluster-selector stringToString   Put the crate's runtime objects on the clusters with these labels, as k=v[,k=v]. Cannot be used with --clusters. (default [])
      --clusters strings                  The clusters to put the crate's runtime objects on. Hub objects and definitions stay on the local cluster.
      --dry-run                           Print the Application without applying it.
  -e, --env string                        specify environment name for application
  -h, --help                              help for deploy
  -n, --namespace string                  specify the Kubernetes namespace to use
      --registry string                   The crate registry to deploy from. Empty means the configured default.
      --timeout duration                  How long to wait for the crate to become healthy. (default 5m0s)
      --version string                    The crate package version (OCI/ECR tag) to install. Empty installs the latest published version.
```
