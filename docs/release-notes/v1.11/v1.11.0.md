## Summary

v1.11 upgrades the CUE engine to v0.14.1 behind a compatibility layer that keeps existing
definitions rendering. It also introduces defkit for writing definitions in Go, a native Helm
component, Application-scoped and global policies, and immutable parameters.

## Compatibility

| Component | Version |
| --- | --- |
| Kubernetes | `>= v1.19, <= v1.31` |
| Go | 1.23.8 |
| CUE | v0.14.1 |
| Kubernetes client libraries | `k8s.io/client-go` v0.31.10, `controller-runtime` v0.19.7 |
| Upgrade from | v1.10.x; see the [upgrade guide](../../upgrade/v1.11/index.md) |

## Breaking changes

### CUE v0.14

CUE v0.14 turns previously-tolerated syntax (list arithmetic, unquoted error field labels) into
hard errors, and enables two new experimental evaluator behaviors (`evalv3`, `keepvalidators`)
that can change how existing definitions behave. The upgrade is non-breaking by default: the
controller renders legacy definitions through an automatic compatibility layer, and the Helm chart
disables the two breaking CUE experiments. See
[CUE 0.14 Compatibility Layer](../../upgrade/v1.11/cue-compatibility-layer.md) to find and
permanently fix affected definitions.

## Behaviour changes

### Application status

The Application `Ready` condition is now `False` after a reconcile failure.
It no longer keeps the `True` value from the previous successful reconcile
([#7168](https://github.com/kubevela/kubevela/pull/7168)).

### Other changes

- `MultiStageComponentApply` is now on by default, so manifests are dispatched in batches by stage.
- Namespace admins can no longer use definitions in `vela-system` without explicit permission
  ([#6972](https://github.com/kubevela/kubevela/pull/6972)).
- The `statusDetails` CUE field in health and status templates is renamed `details`
  ([#7088](https://github.com/kubevela/kubevela/pull/7088)).

## CRD changes

- `PolicyDefinition` (and `DefinitionRevision`) add `spec.scope`, `spec.global` and
  `spec.priority` for Application-scoped and global policies.
- `Application` status adds the applied Application policies, per-component `details`, and
  `workflowRestartScheduledAt`.
- `TraitDefinition` status templates add `details`.
- `Workflow` steps add `mode`.

`applicationrevisions` changes to match. Apply the CRDs before `helm upgrade`.

## Controller flags and feature gates

| Name | Change | Default |
| --- | --- | --- |
| `--enable-cue-version-compatibility`, `--cue-compatibility-cache-size` and the `--cue-upgrade-*` passes | New | See [CUE 0.14 Compatibility Layer](../../upgrade/v1.11/cue-compatibility-layer.md) |
| `EnableApplicationScopedPolicies` | New, Alpha | `false` |
| `EnableGlobalPolicies` | New, Alpha | `false` |
| `ValidateUndeclaredParameters` | New, Alpha | `false` |
| `MultiStageComponentApply` | Default changed | `true` |
| `ValidateDefinitionPermissions`, `EnableApplicationStatusMetrics`, `ValidateResourcesExist` | New since v1.10.0 (shipped in v1.10.4) | `false` |

The controller's flags were reorganised into groups ([#6949](https://github.com/kubevela/kubevela/pull/6949)); flag names are unchanged. Details are in [Controller Flags and Feature Gates](../../platform-engineers/system-operation/bootstrap-parameters.md).

## Helm chart changes

- `workflow.enableCUEVersionCompatibility`, `workflow.cueCompatibilityCacheSize` and the
  `workflow.cueUpgrade*` values configure the CUE compatibility layer.
- `featureGates.enableCueExpVariable` (default `true`) injects
  `CUE_EXPERIMENT=evalv3=0,keepvalidators=0` into the controller.
- `extraEnvs` adds environment variables to the controller container.
- `featureGates.enableApplicationScopedPolicies` and `featureGates.enableGlobalPolicies`.
- `admissionWebhookTimeout` sets the admission webhook timeout in seconds (default `10`).

## CLI changes

- `vela def compatibility-check definitions` and `vela def compatibility-check applications` find
  definitions and Applications that rely on the CUE compatibility layer.
- `vela def upgrade` rewrites a definition for CUE v0.14.
- `vela def init-module`, `gen-module`, `validate-module`, `apply-module` and `list-module` work
  with defkit modules.

Each command's flags are on its page under [vela CLI](../../cli/vela.md).

## New features

- **defkit**: write X-Definitions in Go and generate CUE; see
  [Manage Definition with Go](../../platform-engineers/defkit/overview.md).
- **Native Helm component** and provider, with `valuesFrom` and chart repository authentication.
- **Application-scoped and global policies** that transform an Application before rendering.
- **Immutable parameters** and validation of undeclared parameters.
- Per-Application reconcile interval through the `app.oam.dev/reconcile-interval` annotation.
- The `deploy-components` workflow step, re-running workflows, post-dispatch output context and
  custom errors in components.
- Addon registry tokens are stored in Secrets.

## Bug fixes

- Component removals are persisted and reflected in status.
- Externally deleted apply-once resources are not recreated.
- `appliedResources` is rebuilt from the ResourceTracker.
- `last-applied-configuration` is preserved for shared resources.
- `vela status` no longer reports Healthy when the workflow failed with no services.
- Credentials in Terraform module remote URLs are not logged or persisted.

## Dependencies

v1.11 raises the Go toolchain and Kubernetes client library versions used to build and run
KubeVela:

- **Go**: `1.22.0` → `1.23.8` ([#6767](https://github.com/kubevela/kubevela/pull/6767))
- **Kubernetes client libraries** (`k8s.io/api`, `k8s.io/client-go`, `k8s.io/apimachinery`, etc.): `v0.29.2` → `v0.31.10`, and `sigs.k8s.io/controller-runtime`: `v0.17.6` → `v0.19.7` ([#6837](https://github.com/kubevela/kubevela/pull/6837))
- E2E tests and envtest now run against Kubernetes `v1.31` (previously `v1.29`)

These are neither breaking for end users nor for existing Application/Definition YAML. They matter if you build custom controllers, providers, or addons against KubeVela's Go modules — bump your own `go.mod` and vendored `k8s.io`/`controller-runtime` versions accordingly to stay within a compatible range. The supported Kubernetes cluster version for running KubeVela itself remains `>= v1.19 && <= v1.31` (see [Kubernetes Requirements](../../installation/kubernetes.mdx)).

The versions above are relative to v1.10.0. The same bumps also shipped in the v1.10 patches: Go
1.23.8 in [v1.10.3](../v1.10/v1.10.3.md) and the v0.31 libraries in [v1.10.4](../v1.10/v1.10.4.md).

- CUE `v0.9.2` → `v0.14.1` ([#6877](https://github.com/kubevela/kubevela/pull/6877)).
- `kubevela/workflow` v0.7.2.
